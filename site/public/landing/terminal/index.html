JSX, drawn straight
onto the glass._

mjsx is a UI engine you write in JSX and run on a microcontroller, a Raspberry Pi, a desktop window, a terminal, or a browser tab — from one portable core, unmodified. No virtual DOM, no reconciler: a dirty frame just redraws.

It assumes exactly ten native drawing calls exist. A backend is whatever realizes those ten. That is the entire porting contract, and it is why the same file that drives a 240×280 panel over WiFi also prints itself into the terminal you are about to watch.

  • 2,526 lines of engine
  • 312 lines of JSX transpiler
  • 0 dependencies
  • 10 native calls
  • 6 backends
  • 4 boards in the fleet

01 / The whole porting contract is ten functions

      

        Everything above the line — layout, hit-testing, scrolling, keyboards, modals — is one
        portable file. Below the line is whatever your target can do with a rectangle.
      


      

        
$ wc -l packages/core/src/mjsx.js packages/core/src/jsx.js

        
    2514 packages/core/src/mjsx.js
     312 packages/core/src/jsx.js
    2826 total

        
# the engine, and the JSX transpiler. that is the project.

      


      

        

          docs/contract.md — the ten calls, plus the one clock
          
            
CallMeaning

          
          
            
gfx.clear(color)Fill the whole surface. Start of every frame.

            
gfx.rect(x,y,w,h,color,radius)1px outline, optionally rounded. radius may be 0.

            
gfx.frect(x,y,w,h,color,radius)Filled rect, optionally rounded. The workhorse call.

            
gfx.circle(x,y,r,color,filled)Centre, radius, boolean filled.

            
gfx.line(x0,y0,x1,y1,color)1px line. The core draws thick lines as parallel 1px lines itself.

            
gfx.text(x,y,size,color,str)Draw at an integer size multiplier, top-left origin. The core never rasterizes a glyph; font choice is entirely the backend's.

            
gfx.clip(x,y,w,h)Set the clip rect. A single rect, not a stack — the core intersects nested clips itself and always hands you one honest rect.

            
gfx.unclip()Remove the clip rect.

            
gfx.width()Logical surface width in pixels.

            
gfx.height()Logical surface height.

            
sys.millis()Monotonic clock, milliseconds. Drives timers, cursor blink, long-press, fling velocity.

          
        

      


      

        
    
          
  • No VDOM, no reconciler. Layout is width-in, height-out. A dirty frame is simply redrawn.
    • 
          
  • Hit-testing registers at the exact rect a control was drawn at, so what you tap can never drift from what you see.
    • 
          
  • The touch state machine is in the core — drag slop, scroll, fling, long-press — not re-invented per backend.
    • 
        

        
    
          
  • Written in an ES5 / MicroQuickJS-safe subset on purpose. The same file runs unmodified on a chip's embedded interpreter and in a browser's engine.
    • 
          
  • The JSX transpiler is 312 lines, written in the same subset it compiles — so it runs in a browser, or inside the chip interpreter itself.
    • 
          
  • Zero dependencies. node_modules is empty; SDL2 is the one optional native library, and only for the desktop window.
    • 
        

      

    

  


  
  

    

      
02 / What an app actually looks like

      

        Ambient globals, no imports, no build step. h,
        UI, gfx and sys
        are what a device provides; every example in the repository is one flat file like this
        and runs unmodified under any backend.
      


      

        
$ sed -n '13,25p' examples/counter/app.jsx

      


function App() {
  var count = UI.state.count || 0;
  return (
    <box pad={em(2)} gap={em(2)}>
      <text text={'COUNT: ' + count} size={3} color={UI.theme.text} align="center" />
      <Button label="+1" size={2}
              onTap={function () { UI.set({ count: count + 1 }); }} />
    </box>
  );
}

UI.mount(App);

      

# examples/counter/app.jsx, verbatim. tap the button, the count changes,
# the screen redraws to match. that is the entire state model.


      

        
    
          
  • State goes one way. UI.set marks the frame dirty; the next frame is drawn from scratch. There is no tree to diff and nothing to keep in sync.
    • 
          
  • Text entry is on-device. Four keyboard layouts — QWERTY, T9, a number pad, and a scrolling STRIP for tiny screens — and the layout picks itself from how much room the keys actually get.
    • 
        

        
    
          
  • Hardware is just more JavaScript. sys.gpio reads a pin, drives it, or reads the ADC; sys.i2c scans the bus and peeks registers; a motion module supplies acceleration, rotation and temperature.
    • 
          
  • Canvas sources let a camera frame, or a hundred committed brush strokes, cost exactly one blit.
    • 
        

      

    

  


  
  

    

      
03 / Six ways to answer the same ten calls

      

        Nothing above the contract is special-cased per target. In pure-js,
        gfx.frect writes into an RGBA buffer. On the chip and in wasm it
        is a C function. In the terminal it writes into a sub-pixel buffer that gets flushed as
        escape codes.
      


      

        
$ ls backends/

          backends/ — all six exist and run today
          
            
BackendWhat it is

          
          
            
pure-jsHeadless rasterizer into an RGBA buffer; writes a binary PPM, which the gallery script converts to PNG with an encoder written in the repo. The reference implementation, and the renderer the browser-mirror and desktop backends draw with.

            
terminalNear-square pixels in a terminal — two sub-pixels per character cell via the half-block glyph. Renders once, runs interactively in raw mode, or serves the example picker.

            
sdlDevice simulator in a native window: square, rounded-corner and round-display masks, size presets for the real panels, an HD sub-pixel mode.

            
httpThe UI in a browser tab — pixels out over a socket, real input back, including genuine per-finger multitouch.

            
wasmThe same MicroQuickJS engine C source compiled with Emscripten. Engine parity for testing — the identical bytecode a chip runs, not a reimplementation.

            
esp32The real thing. A minimal reference firmware showing where a panel driver plugs in, plus the bundler that pushes core, shim and every example to a live board over TCP — no reflash.

          
        

      

    

  


  
  

    

      
04 / A four-board fleet, driven daily

      

        All ESP32-S3 touch-LCD boards. An app arrives as a plain JS bundle the firmware
        evaluates, so shipping a change is a push, not a flash; firmware itself updates over
        WiFi, into the inactive slot, verified before the board switches to it.
      


      

        

          docs/devices.md — the boards, selected at build time by flag
          
            

              FlagBoard
              PanelTouch
            

          
          
            
(default)ESP32-S3-Touch-LCD-1.69240x280 ST7789V2CST816T

            
--b35ESP32-S3-Touch-LCD-3.5320x480 ST7796FT6336

            
--b147ESP32-S3-Touch-LCD-1.47172x320 JD9853AXS5106L

            
--b128ESP32-S3-Touch-LCD-1.28 (round)240x240 GC9A01CST816S

          
        

      


      

        
    
          
  • Camera frames stream in as canvas sources — a live preview and full-frame snapshots, blitted by the UI as single ops.
    • 
          
  • A browser mirrors the screen. The device shim records each frame as compact ops and replays them on a /remote page — the receiving end is just another backend.
    • 
        

        
    
          
  • The round board is the constrained one. Its 2MB PSRAM means the JS heap is capped at 1MB, which still runs the full example set with room for the frame canvas.
    • 
          
  • Fleet commands fan out: discovery over mDNS with a TCP probe as the fallback, then push or update every board on the LAN, one result line each.
    • 
        

      

    

  


  
  

    

      
05 / Round glass has no corners, so the layout stops assuming them

      

        On the 1.28" GC9A01 the host tells the core the display is round, and layout answers by
        fitting the chord of the circle at each row's own height — the width the glass
        really has between two y values, minus a hair for the bezel.
      


      

        
$ grep -n "UI.isRound()" packages/core/src/mjsx.js

        
755:      if (UI.isRound()) maxOff += gfx.height() >> 2;
896:  var round = UI.isRound();
1360:  if (UI.isRound()) kbW = kbChordHW(gfx.height() * 0.72, gfx.height() * 0.86) * 2;
1376:  var okInArc = UI.isRound() && layout !== 'strip';
1397:  var rowW = (UI.isRound() ? kbW : gfx.width()) - 8;
1448:    var xTopPad = UI.isRound() ? Math.round(gfx.height() * 0.10) : 0;
1454:    var xBotPad = UI.isRound() ? Math.round(gfx.height() * 0.12) : 0;
1475:    var xRowW = UI.isRound()
1492:    if (UI.isRound()) {

      


      

      

        
    
          
  • The chord, per band. A helper returns half the width the circle really has between two heights, taking whichever edge is farther from the middle — so a row is never wider than the glass under its own worst corner.
    • 
          
  • The keyboard becomes a trapezoid. Its bottom row sits nearest the rim, which is exactly where an un-inset layout would put SPACE and OK half under the bezel.
    • 
        

        
    
          
  • ArcFooter places controls along the edge, wherever the ray from screen-centre meets the boundary. On round glass that is the rim; on square glass the same call walks the rectangle's perimeter. Items stay upright — only their positions follow the edge.
    • 
          
  • The keyboard layout chooses itself from the width it is given: kbW >= 220 gets QWERTY, >= 115 gets T9, and anything narrower gets the scrolling STRIP.
    •
