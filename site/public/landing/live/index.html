mjsx running, not described simulator docs

Play it. That is the pitch.

Below is examples/asteroids/app.jsx from this repository, running on the engine a microcontroller runs, drawn through ten native calls. Hold and drag — the ship steers toward your finger and how far out you hold is the throttle. Tap to fire. Arrow keys and space work too.

240 × 240 · round · GC9A01
hold & drag to fly · tap to fire

The round board is why the control is a drag and not a pair of arrows. Screen thirds and on-screen buttons are rectangle thinking — they assume corners to put controls in and edges to divide. A circle has an angle everywhere, so pointing is the gesture the shape suggests, and it turns out to be the better one on a rectangle too.

Wrapping is the same argument. On a rectangle, leaving the right edge puts you on the left. On a circle the corners do not exist, so a box-wrapped rock vanishes into a region that is not there. Here the boundary is the rim: cross it and you return diametrically opposite, still on glass. That is nine lines, and the only place the file asks UI.isRound().

draw calls · frame — layout+paint — fps — camera —

In CENTRED the ship is pinned to the middle and the world moves past it — which on a 240px circle is the only way to see where you are going. The 1px stars exist for exactly that: with the ship fixed, they are the only thing that tells you the world is moving.

touch is a real event

Draw on it.

examples/canvas/app.jsx, unmodified. Drag on the panel to draw; the swatches change colour. Every stroke is a UI.pointer stroke handed to an onDraw handler — the same call the ESP32 touch controller makes, and the same one the HTTP mirror forwards from a browser.

The palette sits on an ArcFooter: items are placed where the ray from screen centre meets the boundary. On a rectangle that boundary is the perimeter, so the arc flattens onto the bottom edge. One call, both shapes, no branch.

text entry, on a chip

Type on it.

172 × 320 · 1.47″ JD9853
tap a field, then use the keys

examples/input/app.jsx. Tap a field and a keyboard appears — drawn as ordinary boxes, sending the same UI.key('press', name) a physical keyboard sends. There is no privileged channel: a custom pad written in app JSX is a keyboard the moment its taps call that.

On this 172-pixel panel the docked keys would come out under a finger's height, so the keyboard takes the whole display instead and mirrors the field above itself. Nobody opted in to that. The field is not copied either — input state is keyed by id, so the mirror is the field.

one source, five panels, at once

  
No breakpoints. No second code path.

  

    Every panel below is running the same asteroids file, live, at a different
    size. Nothing in it asks what shape it is on except those nine lines of
    wrapping. Layout is width-in, height-out — a node is told its width and
    reports its height — which is why one tree fits a 172-pixel column and a
    480-pixel window.
  

  






  
what it costs

  

    

      
—

      
The whole engine: h(), layout, hit-testing, the touch state
         machine, scrolling, text fields, keyboards. One file.

    

    

      
0 dependencies

      
An empty node_modules. SDL2 is optional, and only for the
         desktop window.

    

    

      
No reconciler

      
No virtual DOM, no diff, no keys. A dirty frame redraws the tree — which
         is what the frame counter above is counting.

    

    

      
ES5, on purpose

      
No classes, no arrows, no template literals — because that is what
         MicroQuickJS on the chip accepts.
