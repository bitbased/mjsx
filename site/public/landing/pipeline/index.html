    Stage 2 is JSX to h() and nothing else — no TypeScript, no
    Babel, no bundler. It deliberately does not touch your object literals, because
    the engine it feeds parses ES5 and a helpful transform that rewrote
    { x: x } to { x } would produce a file the chip
    refuses.
  


  

    
Why there are only four steps

    

      

        
No virtual DOM

        
Nothing is retained between frames and nothing is diffed. A dirty frame
           walks the tree and paints it, which is why stage 3 is a flat list and
           not a mutation log.

      

      

        
No bundler

        
Stage 2 runs in 312 lines, here in your browser and on the machine that
           pushes a bundle to a board. Same file, same output.

      

      

        
Eleven functions

        
Everything in stage 3 is one of ten gfx calls plus a clock.
           A backend is those eleven; the ESP32 binds them to C, the terminal to
           half-block cells.

      

      

        
Width in, height out

        
A node is told its width and reports its height. Change the panel above
           and the tree does not change — only the number it was told.

      

    

  


  

    
The ops are the portable artifact

    

      Stage 3 is not a debug view. That list is what the HTTP mirror streams to put
      a device's screen in a browser, what every figure in the documentation carries
      inside its PNG, and what the golden tests hash. Because it is resolution
      independent, the same recording replays at any scale — text is redrawn with a
      larger face rather than magnified.
    

    

      Which is also the honest measure of the engine's size: what you see in stage 3
      is everything mjsx asks a device for. There is no second channel.
